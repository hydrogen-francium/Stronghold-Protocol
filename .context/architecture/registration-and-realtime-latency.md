# 注册授权与实时延迟

## Context（上下文）

2026-10-22，用户要求共享密钥仅在注册时使用，并报告三人联机延迟达到三位数。优化不得改变战斗结果、伪造延迟显示或缓存已撤销的授权。

## Fact / Pitfall（事实与坑点）

- 原实现把十二小时注册凭证与七天账号会话绑定，导致后续登录和连接仍需共享密钥。`admitted` 仅描述注册授权，不能用作账号是否登录的判断。
- 实时连接在入站消息、心跳、排队执行和异步回复等边界重新校验会话。旧查询每次读取完整账号并解析密码记录；不是只有连接时执行一次。
- 原版战斗在页面主线程执行，调度器追赶最多一次推进 240 刻，展示前准备最多一次推进 600 刻。单纯限制刻数不能限制主线程阻塞时间。
- 浏览器显示的往返延迟包含网络与两端事件循环等待。本地结果不能证明目标服务器三人公网延迟已降到某数值。

## Solution / Convention（解决方案与规约）

1. 登录页默认展示账号密码。注册标签先校验共享令牌，再注册；注册和登录成功均清除注册凭证。账号会话及配对防伪 Cookie 有效期均为七天，过期后输入账号密码即可。
2. 注册仍需有效 `sp_gate`；所有认证写请求保留精确来源、防伪和限速检查。WebSocket 只依赖账号会话，注销、封禁、改密及会话过期仍立即通过数据库校验阻断。更换注册令牌不影响已有账号登录；更换会话秘密仍使旧会话失效。
3. `AuthStore.validateSession` 使用预编译布尔查询，每次重新检查会话摘要、账号、禁用状态、凭据版本及有效期，不解析密码记录，也不缓存授权。
4. 页面战斗宿主接受时间预算，调度器每次推进给出 8 毫秒软预算，在完整模拟刻之后让出主线程，后续继续追赶。单刻不能中断，因此不保证每次严格小于 8 毫秒。工作线程路径保持不变；不修改确定性引擎或延迟数值。
5. 不迁移数据库、不重下素材、不改 Nginx。用户更新镜像并重建应用容器；重建会结束当前内存对局。线上公网延迟需要部署后实际验收。

## Verification（验证）

- 2026-10-23 收尾：实际 Edge 浏览器通过默认登录、注册入口要求令牌、账号密码登录后进入游戏并建立在线连接的验证；登录后不存在 `sp_gate`。
- 时间预算专项用已知较慢的模拟刻确认提前返回，合并分片与尾部事件后无遗漏、无重复。认证、预算和正式第三回合规格的本地专项共五项通过；另运行现有账号存储与战斗调度器定向用例。
- 本地定向验证覆盖无令牌登录及连接、无授权注册拒绝、来源及防伪拒绝、注销断开、跨十二小时账号有效、封禁及恢复不复活旧会话。
- 使用三真人一名 AI 的正式第三回合战斗规格，对比分片前后完整战斗结果，要求一致。
- 本地测试脚本不提交；提交前验证结果以本次交付说明为准，不把本地脚本路径当作远端测试入口。
