# 表情已发送但被队友栏裁剪

## Context（上下文）

- 2026-10-22，用户反馈对局表情发不出去。
- 适用于 `TeamPanel` 的表情气泡显示；不涉及准入令牌、聊天权限或表情协议变更。

## Fact / Pitfall（事实与坑点）

- 扩展人数展示为 `.team` 增加了 `overflow-y: auto; overflow-x: hidden`，但 `.team__bubble` 仍以 `left: calc(100% + .06rem)` 放在成员行的右边。
- 原右内边距仅 `.12rem`，不足以容纳 `emotes.css` 中宽 `1.08rem` 的气泡，图片实际位于滚动容器外。因此服务端已经广播、客户端状态已收到，界面却看不到图片。
- 本地真实账号、一名真人与三名 AI 的正式对局复现：桌面 1440×900 下，队友栏右边界为 `172.875px`，本人的表情图片位于 `187.875px` 至 `238.875px`，整张图片被裁剪。
- 仅检查 `g.emote` 成功、`m.emote` 回传或者气泡节点存在，不能证明表情可见。

## Solution / Convention（解决方案与规约）

1. 保留纵向滚动及高度限制，不能为修复四人表情而恢复十六席越界。
2. 队友栏右内边距改为 `1.26rem`，包含气泡宽度 `1.08rem`、行外间距 `.06rem` 与 `.12rem` 动画余量；上下内边距为 `.2rem`，保护首尾气泡的放大动画。
3. 成员行原本的内容宽度和表情锚点不变，不修改冷却、协议、广播或素材路径。本次实测成员行宽度始终为 `144.375px`；修复后的栏右边界为 `258.375px`，图片留在可视区内。
4. 修改气泡尺寸、锚点、放大比例或队友栏滚动时，必须同时检查气泡图片与整个气泡的裁剪边界。

### 验证记录

- 真实 Edge 浏览器通过正式认证、建房、添加三名 AI、开局、策略选择、点击交流与表情，确认本人收到服务端回传并显示气泡，无页面异常。
- 使用正式 `TeamPanel` 组件构造四、八、十六席展示，检查桌面 1440×900、手机横屏 844×390、竖屏 390×844 下的首尾气泡；将气泡设为动画峰值 `1.1` 倍时仍留在可视区内；短视口十六席保留纵向滚动。
- 表情目录、白名单、冷却、广播、AI 回应及动态人数回归，加浏览器检查共 `50 tests / 47 pass / 0 fail / 3 skipped`。三项跳过仅因本地没有官方原始表或提取素材清单。
- 浏览器验收脚本为本地忽略文件，不提交测试、素材或开发页面；上述布局验收不代表真实十六人完整对局或生产服务器已经验证。
